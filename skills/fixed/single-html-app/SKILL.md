# 단일 HTML 앱 제작 규칙

학생이 휴대폰으로 여는 단일 HTML 웹앱과 활동지를 만들 때 쓴다. 진단 도구, 활동지, 진행보드, 게임처럼 파일 하나로 끝나는 결과물이 모두 해당한다. 사용자가 따로 말하지 않아도 이 규칙을 적용하고, 마지막 점검 절차까지 수행한다.

## 1. 파일을 쪼개서 만든다

한 파일에 수십만 자를 넣으면 부분 수정이 불가능해진다. 역할별로 파트 파일을 나누고 이어 붙여 완성본을 만든다.

```
p1.html   제목, 글꼴 링크, 토큰과 전체 CSS, 상단 막대와 셸 마크업, <script> 시작
p2~pN.js  데이터 (문항, 표, 사전 등 큰 덩어리를 따로)
pX.js     엔진 (상태, 저장, 화면 전환, 공용 함수)
pY.js     화면 함수
pZ.js     마지막 호출과 </script>
```

```bash
cat p1.html p2.js ... pZ.js > app.html
```

- 수정은 언제나 파트 파일에 하고 완성본은 다시 이어 붙인다. 완성본을 직접 고치면 다음 빌드에서 사라진다.
- 파이썬으로 문자열을 바꿀 때는 `assert s.count(old)==1`을 먼저 걸어, 의도한 자리 하나만 바뀌는지 확인한다.
- 데이터가 늘어나면 새 파트 파일을 만들고 빌드 명령에 끼워 넣는다. 끼우는 자리는 함수 선언 호이스팅이 통하므로 마지막 호출 파일보다 앞이면 된다.

## 2. 화면 뼈대

- 색은 전부 `:root`에 토큰으로 선언한다. 어두운 화면은 `@media (prefers-color-scheme:dark) :root:not([data-theme="light"])`와 `:root[data-theme="dark"]` 두 곳에서 같은 값으로 다시 선언한다. 한쪽에만 있는 색은 반드시 깨진다.
- `body`에 배경색을 명시한다. 투명하면 바깥 배경이 비친다.
- 셸은 `max-width:480px`, 세로 flex로 두고 본문에 `flex:1`을 주어 하단 서명이 바닥에 붙게 한다.
- 상단 고정 막대는 `top:env(safe-area-inset-top, 0px)`를 쓴다.
- 한국어 본문에는 `word-break:keep-all; overflow-wrap:break-word`를 준다.
- 폭 412px에서 가로 스크롤이 생기면 안 된다. 표와 코드만 각자 `overflow-x:auto` 상자에 넣는다.
- 하단에 `© shiny-peace` 서명 한 줄을 둔다. 특정 화면이 아니라 셸 바닥에 두어 모든 화면에 나오게 한다.

## 3. 아티팩트에서 되는 것과 안 되는 것

공유 링크로 열리는 화면은 제약이 있다. 아래를 지키지 않으면 교실에서 눌러도 아무 일이 일어나지 않는다.

- `window.print()`는 동작하지 않는다. 인쇄 단추를 두지 말고, 종이가 필요하면 걷은 글을 문서에 붙여 인쇄하도록 안내한다.
- `alert`, `confirm`, `prompt`는 뜨지 않는다. 확인 절차는 화면 안에 만든다. 지우기 같은 되돌릴 수 없는 동작은 한 번 더 눌러야 실행되게 한다.
- 페이지가 스스로 시작하는 내려받기는 막힌다. 파일 저장은 `downloads` 기능을 선언하고 `window.claude.use('downloads')`로 받아 쓰되, 없을 때는 단추를 숨긴다.
- 외부 스크립트는 cdnjs 등 허용된 곳에서만 불러온다. 글꼴은 Google Fonts만 된다. 나머지는 전부 파일 안에 넣는다.
- 다른 사이트를 iframe으로 넣을 수 없다. 링크로 내보낸다.
- `localStorage`는 되지만 비어 돌아오거나 예외를 던질 수 있다. 읽기와 쓰기를 모두 try/catch로 감싸고, 저장이 없어도 화면이 정상으로 그려지게 한다.

## 4. 화면 이동

- 상단 막대는 아이콘으로 정리한다. 왼쪽에 뒤로, 오른쪽에 홈과 점 세 개 메뉴를 두고, 나머지 항목은 메뉴 안으로 접는다.
- 뒤로는 화면 기록 스택으로 구현한다. 화면 함수마다 첫 줄에서 자기 상태를 기록하고, 뒤로는 현재와 직전을 꺼낸 뒤 직전 화면 함수를 다시 부른다.
- 같은 화면을 가리키는 단추는 이름을 하나로 통일한다. 안쪽에만 있는 입구가 생기지 않도록, 주요 입구는 첫 화면에도 둔다.
- 긴 글은 카드로 나누어 넘기게 한다. 중간에 선택형 물음을 끼우면 교실에서 함께 읽는 자료가 된다. 고르기 전에는 다음으로 넘어가지 못하게 하고, 다음 장에 자기가 고른 답을 먼저 보여 준다.

## 5. 저장과 제출

- 저장 키는 앱당 하나로 묶는다. 기능이 늘어나도 키를 쪼개지 말고 객체 안에 칸을 더한다.
- 학생 결과는 서버로 보낼 수 없다. 결과 복사 단추로 한 덩어리 글을 클립보드에 담고, 구글 폼 장문형에 붙여넣어 제출하게 한다.
- 복사는 `navigator.clipboard.writeText`를 먼저 쓰고, 거부되면 임시 textarea를 만들어 `execCommand('copy')`로 넘어간다.
- 결과 글은 사람이 읽을 수 있으면서 나중에 앱스스크립트로 쪼갤 수 있게, 머리글과 항목 이름을 일정한 모양으로 적는다.

## 6. 학생용 문안

- plain-korean 스킬 규칙을 먼저 적용한다.
- 장면을 먼저 세우고 안내한다. 단답 지시문으로 쓰지 않는다.
- 비유를 술어 자리에 쓰지 않는다. "전공이 문이다" 같은 문장은 "전공을 요구한다"로 고친다.
- 같은 비유를 한 화면에서 되풀이하지 않는다.
- 고등학교 수업은 50분, 중학교는 45분으로 잡는다.
- 숫자를 학생에게 보여 줄 때는 그 숫자가 무엇을 뜻하는지 한 줄을 반드시 붙인다.

## 7. 접근성

- 선택지는 `role="radiogroup"`과 `role="radio"`, `aria-checked`를 쓴다. 탭은 `role="tablist"`, `role="tab"`, `role="tabpanel"`로 잇는다.
- 접었다 펴는 칸은 `aria-expanded`와 `aria-controls`를 붙인다.
- 화면을 바꾼 뒤 첫 제목에 초점을 옮긴다. 이때 제목의 기본 외곽선은 지운다.
- 모든 입력 칸에 `label`을 붙이고 `id`를 고정한다.
- `prefers-reduced-motion`에서 전환 효과를 끈다.

## 8. 내보내기 전 점검

순서대로 수행한다. 하나라도 건너뛰지 않는다.

1. **문법** — 완성본에서 `<script>` 안을 뽑아 `node --check`로 확인한다.
2. **데이터 무결성** — `document`와 `localStorage`를 흉내 낸 노드 하네스로 전역 데이터를 꺼내, 키 개수가 맞는지, 서로 가리키는 값이 실제로 있는지, 빠진 항목이 없는지 전수로 확인한다.
3. **화면** — Playwright로 폭 412px, 밝은 화면과 어두운 화면 두 번 돌린다. `pageerror`와 콘솔 오류를 모으고, `document.documentElement.scrollWidth <= window.innerWidth + 1`을 확인한다. 주요 흐름을 실제로 눌러서 끝까지 지나간다.
4. **문장** — 새로 쓴 한국어 문장만 뽑아 plain-korean 검수 스크립트에 넣는다. 공고 원문이나 인용은 원문 그대로 두어야 하므로 검수 대상에서 뺀다.
5. **화면 확인** — 바뀐 화면을 밝은 쪽과 어두운 쪽 각각 한 장씩 캡처해 직접 본다.

점검 스크립트는 파일로 남겨 두고 고칠 때마다 다시 돌린다. 선택자가 바뀌면 스크립트도 함께 고친다.

## 9. 발행

- 같은 파일 경로로 다시 발행하면 같은 주소가 유지된다. 경로를 바꾸면 새 주소가 생기므로 바꾸지 않는다.
- 처음 발행할 때만 아이콘을 넘기고, 다시 발행할 때는 넘기지 않는다.
- 발행한 뒤에는 무엇이 바뀌었는지 한두 문장으로만 말한다. 주소는 사용자가 묻지 않으면 적지 않는다.
- 댓글이 오면 고친 다음 그 스레드에 답을 남기고 해결로 표시한다. 무엇을 어떻게 왜 고쳤는지, 함께 바꾼 자리가 있으면 그것까지 적는다.

## 함정

- 어두운 화면 색을 `@media` 블록 한쪽에만 선언하면 깨진다. `:root:not([data-theme="light"])`와 `:root[data-theme="dark"]` 두 곳에 같은 값을 넣는다.
- `body`에 배경색을 빼면 바깥 배경이 비친다.
- 아티팩트에서는 `window.print()`, `alert`, `confirm`, `prompt`가 동작하지 않는다. 교실에서 눌러도 아무 일이 일어나지 않는다.
- `localStorage`는 비어 돌아오거나 예외를 던질 수 있다. 읽기와 쓰기를 모두 try/catch로 감싼다.
- 완성본(app.html)을 직접 고치면 다음 빌드에서 사라진다. 언제나 파트 파일을 고친다.
