# 연수 진행보드 설계

손평화 선생님의 연수 진행보드를 만들거나 고칠 때 쓴다. 좌측 시각 목차 + 우측 한 장씩 전환, 참가자·강사·전체 모드, 경과 타이머, 프롬프트 복사 버튼, 결과물 체크와 진행 막대, 하단 저작권 표기가 기본 구조이다.

## 1. 만들기 전에 반드시 확인한다

아래를 모르면 **추측해서 채우지 말고 먼저 묻는다.** 지어낸 값은 나중에 전부 고쳐야 한다.

1. **실제 시각** — 몇 시부터 몇 시까지인가. 추측 금지.
2. **대상과 차시 길이** — 고등은 50분, 중등은 45분. 참석자의 학교급 비율을 묻는다.
3. **참석자 수준** — 입문인가, 어느 정도 익숙한가, 편차가 큰가.
4. **도구 제약** — 구독 여부, 계정 종류, 연수장 망 상태.
5. **이미 만들어 둔 자산** — 앞서 만든 앱·시트·문서·영상의 **주소**. 받기 전에 카드를 만들어 비워 두지 말 것.
6. **공유보드 주소** — 행사마다 다르다. 이전 행사 주소를 그대로 두면 참석자가 엉뚱한 보드에 올린다.
7. **실제 업무 비중** — 그 직종이 자료 만드는 데 시간을 가장 많이 쓰는 일이 무엇인가. 상상해서 쓰지 말 것.

특히 7번을 놓치면 수업 장면 자체를 잘못 그린다. 예) 자기이해 수업은 검사 결과를 학생이 활동지에 옮겨 적는 방식이지, AI가 성향 문항을 만들어 주는 방식이 아니다.

## 2. 블록 설계 규칙

- **축은 하나다.** 블록마다 다루는 기술이 달라지더라도, 앞 블록의 산출물이 다음 블록의 재료가 되어야 한다.
- **되돌아가지 않는다.** 블록 5에서 블록 4의 방식(붙여넣기 단일 HTML)을 다시 쓰면 참석자가 헷갈린다. 블록마다 구조가 무엇이 다른지 첫 장에서 표로 못 박는다.
- **성격이 다른 것은 부록으로 내린다.** 본론 흐름과 맞지 않는 소재(예: 에이전트 조사)는 마무리 뒤 부록으로 옮기고 시각을 뺀다.
- **넘치게 준비하되 접을 구간을 표시한다.** 시간에 맞추어 내용을 덜어내지 않는다. 대신 당일 접을 수 있는 구간을 정해 둔다.

## 3. 슬라이드 작성 규칙

- **프롬프트 상자에는 붙여넣으면 바로 돌아가는 것만 넣는다.** 빈칸 메모 문장이나 직접 적을 틀을 복사 버튼 달아 넣지 않는다. 붙여넣었을 때 아무 일도 안 일어나면 그건 프롬프트가 아니다.
- **같은 내용을 두 장에 쓰지 않는다.** 앞 장의 표가 뒷장 지침의 목차라면 합친다. 이론을 먼저 강의하고 같은 것을 다시 실습하게 하는 구조를 경계한다.
- **한 줄짜리 안내를 위해 장을 따로 두지 않는다.** 뒤 프롬프트에 이미 칸이 있다면 그 앞에서 같은 것을 적게 하는 것은 일을 두 번 시키는 것이다.
- **각 장의 첫 문장이 앞 장의 결과를 받는지 확인한다.** “첫 실습은 …” 같은 말을 쓸 때 그 앞에 이미 실습이 있었는지 돌아본다.
- **반복되는 것은 Gem으로 넣는다.** 긴 프롬프트를 먼저 시키고 나중에 “매번 쓰기 어려우니 Gem에 담으세요” 하는 순서는 거꾸로된 것이다. Gem을 먼저 만들고 이후 실습을 전부 그것으로 한다.
- **링크 자리를 비워 두지 않는다.** 주소가 없으면 카드를 만들지 말고, 먼저 주소를 물어본다.

## 4. 시간 배분 실측치

아래보다 짧게 잡으면 현장에서 반드시 밀린다.

| 작업 | 최소 시간 |
| --- | --- |
| 도구 열기·로그인 | 5분 |
| 프롬프트 한 번 돌려 결과 보기 | 5분 |
| Gem 만들기 | 10분 |
| 활동지 제작과 다듬기 | 15분 |
| 단일 HTML 1단계 생성 | 10분 |
| 단일 HTML 2단계까지 | 20분 |
| 앱스스크립트 복붙 배포(권한 승인 포함) | 10분 |
| 내 앱스스크립트 만들기 | 10분 |
| 공유보드에 올리고 서로 보기 | 5분 |

배포는 권한 승인 화면에서 반드시 한 명 이상 막힌다. 그 시간을 미리 넣는다.

## 5. 문안 규칙

- 학생용·참가자용 문안은 **장면과 맥락을 먼저 세우고** 활동을 안내하는 서술형으로 쓴다. 단답 지시문 금지.
- 말투는 교과서적인 설명체. 구어체와 과장된 표현을 쓰지 않는다.
- 표 셀 텍스트는 줄 수를 맞추고, 칸에 비해 너무 짧게 끝나지 않게 분량을 조절한다.
- 불릿은 위에서 아래로 줄이 점점 길어지는 계단식으로 배치한다.
- 강사 메모(`.note`)는 손글씨체로, 한 장에 하나만. 진행자가 실제로 입 밖으로 낼 말을 적는다.
- 강사의 사업적 판단이나 도구 구독 사정 같은 내부 사정은 기획안에만 남기고 교안 문안에는 넣지 않는다.

## 6. 내보내기 전 자가 점검

파일을 드리기 전에 직접 돌려본다.

```python
import re, collections
s = open(PATH, encoding="utf-8").read()
ids = re.findall(r'id="([^"]+)"', s)
print("중복 id:", [k for k,v in collections.Counter(ids).items() if v>1] or "없음")
print("section:", len(re.findall(r'<section class="slide', s)), "/ 닫힘:", s.count("</section>"))
print("prompt:", len(re.findall(r'class="prompt"', s)), "/ copy:", len(re.findall(r'class="copy"', s)))
print("pos-t:", re.search(r'pos-t">(\d+)', s).group(1))
print("빈 자리:", re.findall(r'<span class="go">([^<]*)</span>', s))
t = [(m.group(1), m.group(2)) for m in re.finditer(r'data-time="([^"]*)" data-nav="([^"]*)"', s)]
for a, b in zip(t, t[1:]):
    print(a[0], a[1])
```

손으로 확인할 것.

- [ ] 시각이 순서대로 증가하는가. 목차 순서와 시각이 엇갈리지 않는가
- [ ] 시간표 슬라이드의 시각이 실제 슬라이드 시각과 같은가
- [ ] 체크포인트·휴식 문구의 시각이 본문과 맞는가
- [ ] 결과물 체크 개수와 진행 막대 표기가 같은가
- [ ] 빈 링크 자리가 남아 있지 않은가
- [ ] 모든 프롬프트 상자가 붙여넣으면 실제로 돌아가는가
- [ ] 중복되는 장이 없는가
- [ ] 어느 장에서든 바로 합류한 참가자가 따라올 수 있는가

## 7. 보고할 때

고친 내용을 열거하기 전에, **내가 지어낸 것과 확인해야 할 것을 먼저 밝힌다.** 비워 둔 자리가 있으면 목록으로 제시한다. 마지막에 직접 판단을 달고, 시간이 모자라는 구간이 있으면 숫자로 드러낸다.

## 함정

- 이전 행사의 공유보드 주소를 그대로 두면 참석자가 엉뚱한 보드에 올린다. 행사마다 주소를 새로 받는다.
- 앱스스크립트 배포는 권한 승인 화면에서 한 명 이상 꼭 막힌다. 그 시간을 시간표에 미리 넣는다.
- 수업 장면을 상상해서 쓰면 틀린다. 예를 들어 자기이해 수업은 검사 결과를 학생이 활동지에 옮겨 적는 방식이지, AI가 성향 문항을 만드는 방식이 아니다. 실제 업무 비중을 먼저 묻는다.
- 긴 프롬프트를 먼저 시키고 나중에 Gem에 담게 하면 순서가 거꾸로다. Gem을 먼저 만든다.
- 주소를 받기 전에 링크 카드를 만들어 비워 두지 않는다.
